# autorun v1.0.0

Date: 2026-10-31

autorun 1.0.0 is the first stable release. autorun puts a gate in front of an
AI coding agent's tool calls, for example stopping `rm -rf` before it runs and
suggesting `trash` instead, on Claude Code, Google Antigravity, Qwen Code, Codex
CLI, Pi, ForgeCode, and OpenCode. Since 1.0.0rc3, a review of every module
fixed ways past the guards (an `/ar:ok` allow approved the whole command line,
and commands run through a wrapper or a shell went unchecked), an
`autorun --update` that installed unreleased code, an `autorun --no-bootstrap`
that blocked every tool call, task statuses that a harness's own task list
overwrote, installs that removed another harness's plugin, and failures in
`/ar:tabs`, `/ar:tabw`, plan export, and `extract-pdfs`. Task state and the
`/ar` commands carry over from rc3; two default guards that never fired now do,
and `/ar:no` reads several words as one pattern (see Changed).

## Upgrading from 1.0.0rc3

If you installed only through the Claude Code marketplace, run this instead of
the commands below, then restart Claude Code. The first half fetches the new
release into Claude's copy of the marketplace. That route does not run `autorun
--install`, so any setting this section says the install changes is yours to
add.

```bash
claude plugin marketplace update autorun && claude plugin update ar@autorun
```

Otherwise run one of these. Use the second if you installed the PDF
backends (`uv tool list --show-extras` lists `pdf`); the first removes them.

```bash
uv tool install --force 'autorun-ai==1.0.0' && autorun --install
```

```bash
uv tool install --force 'autorun-ai[pdf]==1.0.0' && autorun --install
```

1. Check that `autorun --version` prints `autorun 1.0.0`.
2. Restart open agent sessions. Each one reads its hooks only when it starts.
3. New installs use the same commands. The README covers other harnesses and
   options: <https://github.com/ahundt/autorun#readme>.

`autorun --install` republishes what each harness loads and restarts the
autorun daemon, as it did for rc3. There is no new setting to add, including
for a Claude Code marketplace-only install. Agent sessions already running are
served by the restarted daemon. `uv tool list` shows `autorun-ai` if you
installed with uv. From 1.0.0rc1, use the same commands; the 1.0.0rc3 notes
describe what changed between rc1 and rc3.

## Changed

1. The default `echo >` rule now blocks `echo ... > file`. It matched only when
   autorun could not parse the command, so it almost never fired. Allow one use
   with `/ar:ok 'echo >'`.
2. `git stash clear`, which deletes every stash at once, is now blocked while a
   stash exists, as `git stash drop` already was. Allow one use with
   `/ar:ok 'git stash clear'`.
3. `/ar:no` reads its pattern the way `/ar:ok` does: `/ar:no git push` blocks
   `git push` rather than `git`, and removes an `/ar:ok git push` allow. A
   custom message needs a quoted, `regex:`, or `glob:` pattern:
   `/ar:no "rm" use trash instead`.

## Removed

1. Nine configuration keys that nothing read: `stage1_completion`,
   `stage2_completion`, `stage3_completion`, `recheck_template`,
   `plan_accepted_marker`, `monitor_stop_delay_seconds`,
   `task_staleness_no_tasks_threshold`, `task_staleness_threshold`, and
   `shared_agents_plugins_subdir`. A value for one of them in
   `autorun.config.json` changed nothing; it is now skipped as an unknown key,
   and `autorun --status` no longer reports it.

## Fixed

1. When `~/plugins/ar` already existed as an empty directory,
   `autorun --install` kept it as yours, registered Codex's `ar` plugin there
   anyway, and reported success, leaving Codex with a plugin that had no files
   (`ls -A ~/plugins/ar` printed nothing). It now fills an empty directory, and
   still leaves alone any directory that has content in it or is reached through
   a symlink.
2. On a machine where Qwen Code had never run, the first `autorun --install`
   left Qwen's task tool off (`tools.todoWrite.enabled` in
   `~/.qwen/settings.json`) and said nothing, so Qwen sessions had no
   `todo_write` and autorun did not enforce task tracking there until a second
   install. One install now turns it on.
3. The `/ar:tabw` "set mode" action pressed Shift+Tab into a tmux session named
   after the window number instead of the window you chose, and reported
   success whatever mode resulted. It now cycles the chosen window, reads its
   status line after each press, and reports failure if the mode never appears.
4. `/ar:tabs` failed with a `TypeError` on every run before listing any
   session. It now lists them.
5. `extract-pdfs` on a folder whose subfolders held PDFs with the same name,
   such as `a/report.pdf` and `b/report.pdf`, wrote a single `report.md`: the
   second PDF was skipped as already extracted, or with `--no-resume` it
   overwrote the first. Output now mirrors the input folders, and folder mode
   honors `--format txt`, which it used to ignore.
6. With only the `pdf-llm` or `pdf-gpu` extra installed, `extract-pdfs` said "No
   extraction backend installed" although `--list-backends` listed one. It now
   tries every installed backend.
7. With two sessions planning in one project, leaving plan mode in one session
   backed up the other session's plan. After an accept that clears context, the
   other session's unfinished plan was exported as accepted and the plan you
   accepted was filed as not accepted. Each session now uses its own newest
   plan.
8. `/ar:pe dir` with an absolute folder archived the plan but reported "Plan
   export FAILED ... NOT archived", and a `~/...` folder created a directory
   literally named `~` inside the project. Both now export where you asked.
9. With `/ar:pe rejected off`, a plan you never accepted was written to the
   accepted `notes/` folder. It is no longer written anywhere.
10. `/ar:pe status` showed `notes` as the export folder for a configuration
    using the older `output_dir` key, while exports went to that folder. Status
    now shows where exports actually go.
11. Commands started through a wrapper or a shell skipped every guard:
    `nohup rm -rf x`, `time rm -rf x`, `echo x | xargs rm -rf`,
    `bash -lc 'rm -rf x'`, a multi-line `bash -c`, `bash <<EOF`,
    `echo '...' | sh`, `eval`, and `find ... -exec rm` all ran unchecked.
    autorun now checks the command inside these, and inside `command`, `exec`,
    `doas`, `pkexec`, `stdbuf`, `strace`, `ltrace`, `watch`, `fakeroot`,
    `firejail`, and `bwrap`.
12. `git clean --force` and `git add --all` skipped the `git clean -f` and
    `git add -A` rules. The long forms now match, and `/ar:ok 'git clean -f'`
    also allows `--force`.
13. A commit message passed through a heredoc with a quoted delimiter, such as
    `<<-'EOF'` or `<<'END-MSG'`, was read line by line as commands, so a
    message line like `rm stale helper` was blocked as `rm`.
14. A Bash command starting with `/ar:` was approved without any check, so
    `/ar:x; rm -rf ~/important` ran the `rm`.
15. An `/ar:ok` allow approved the whole command line: after `/ar:ok rm`,
    `rm -rf build && git push --force origin main` ran, force push included.
    An allow now covers only the commands in the line that it matches.
16. A one-use `/ar:ok` could be spent more than once: by two hooks at the same
    moment, or by repeating the same call less than a second apart, without
    limit.
17. Codex: setting `codex_plugin_source_dir` moved autorun's Codex plugin but
    not its entry in `~/.agents/plugins/marketplace.json`, so Codex looked for
    the plugin where it no longer was. The entry now follows the setting. A
    location outside your home folder, which Codex refuses, is refused before
    anything is written, and a `~/plugins/ar` that autorun did not create is
    left alone, kept out of the marketplace, and named in a warning.
18. Some installs removed what another harness or plugin still used:
    `autorun --install --gemini` removed Antigravity's
    `~/.gemini/config/plugins/ar`; with a Codex-type custom harness,
    `autorun --install --claude` removed `~/plugins/ar` while the marketplace
    still listed it; an install without `--custom-harness` removed the
    extension of a Gemini-type harness given only by that flag; and
    `autorun --uninstall pdf-extractor` removed `ar`'s old marketplace entry.
    Each run now changes only the harnesses and plugins it was given.
19. An interrupt or a full disk at the wrong moment of an install, or of
    `autorun --uninstall --force`, could delete the only copy of a directory
    being replaced, such as your own `commands/` folder. It is now put back, or
    saved under `~/.autorun/installer/backups/` when its place was taken.
20. A `.DS_Store` that Finder wrote into an installed folder made every later
    install report "you edited files we installed (.DS_Store)", and uninstall
    kept the folder. `.DS_Store`, `._*`, `Thumbs.db`, and `desktop.ini` are now
    ignored. A Codex plugin installed from a checkout no longer includes its
    `tests/` folder.
21. Setting `AUTORUN_BUG_CLAUDE_CODE_NO_TOKEN_COUNT_FOR_HOOKS_BUG_54673_WORKAROUND_ENABLED`
    to false left the block an earlier install wrote into `~/.claude/CLAUDE.md`.
    The next install now removes it.
22. On Windows, every `autorun --install` ended with "Daemon did not start" and
    exit code 1: the daemon's start-up program was invalid Python for any path
    containing `\U`, as in `C:\Users\...`. A path containing `'` broke it on
    any system.
23. On Python 3.11 and later, a daemon slower than the response timeout was
    sent the same hook again and again, and the hook then reported "Daemon
    failed to start". The Pi, Prime Agent, and OpenCode bridges likewise sent a
    timed-out tool call a second time. A hook is now sent once, and a slow
    answer is reported as "Daemon accepted the request but did not answer".
24. When two hooks wrote autorun's state at the same moment, the one that
    waited reported that its value "has been discarded", and message delivery
    did not retry. It is now treated as lock contention and retried.
25. In Pi, Prime Agent, and OpenCode, `AUTORUN_DISABLE=1`, the way out that
    every block message names, did nothing while the daemon was running, and
    block messages said to retry, which does not help. Both now match the
    other harnesses.
26. Antigravity: when an autorun handler failed or timed out on an event other
    than a tool call, such as Stop, Antigravity was sent Claude Code's
    response fields. Failures now use Antigravity's own format.
27. When autorun installed its own dependencies in the background and that
    took longer than 60 seconds, the next hook started a second install
    alongside the first. It now waits for the first to finish.
28. A hook that fell back to running the `autorun` command wrote that
    command's whole output to `~/.autorun/hook_entry_debug.log`; it now logs a
    bounded excerpt.
29. `autorun task gc` deleted sessions whose tasks were paused or delegated.
    It now keeps any session with a task it cannot prune.
30. Codex's `update_plan` and Gemini's `write_todos` overwrote the statuses
    autorun sets, so a task you ignored, paused, or delegated went back to
    pending or in progress. Those statuses are now kept unless the harness
    reports the task completed or deleted.
31. On Pi and Prime Agent, autorun read its own Stop message, which shows the
    stale-task marker filled in with real task ids, as the agent asking to
    clear those tasks, and cleared them. On Claude Code, the same marker in the
    agent's final reply was not read. Markers now count only in the newest
    assistant message or a tool result.
32. A lock timeout in `~/.autorun/task-lifecycle.config.json` that was a
    string, zero, negative, or infinite turned the Stop gate off. Such a value
    now falls back to the default.
33. The session-start task summary listed only in-progress and pending tasks,
    so a delegation waiting for you to verify it showed only as "and 1 more".
    Every blocking task is now named, and a returned delegation says to verify
    the results.
34. `/ar:tabs` missed Claude in a window split into panes, and counted any
    process with `claude` in its arguments, such as
    `vim ~/.claude/settings.json`, as Claude, so `/ar:tabs all:continue` could
    type into it.
35. In `/ar:tabs`, `awaiting` was read as the session letters A, W, A, I, ...;
    `all` with 12 or more sessions reached A, L, L; a mistyped letter group was
    dropped while the rest ran; and selecting a session typed its suggested
    action, such as "let it work", into Claude. An invalid selection now sends
    nothing and says why, and only `continue` and `interrupt` are sent as
    default actions.
36. `/ar:tabw continue` refused to send at Claude Code's own `❯` prompt
    ("unknown_state"), and `/ar:tabs` marked a window as awaiting input when
    its output said "waiting for build".
37. A tmux window whose title, path, or session name contained `|` disappeared
    from `/ar:tabs` and `/ar:tabw`.
38. autorun's tmux helpers took the tmux server's process id from `$TMUX` as
    the current session's name, so a prompt meant for the current session
    created a new session with that number as its name and typed into it.
39. Bug-workaround keys in `autorun.config.json` accepted only `true` or
    `false`; `"always"`, `"never"`, `"auto"`, and version ranges, which the
    documentation lists, were dropped without a word. They now load, and the
    installer honors them too: `"never"` for the CLAUDE.md workaround now
    keeps the block out.
40. Gemini CLI started an autorun hook process after every model response, and
    Gemini CLI and Qwen Code at every session end, for events autorun does
    nothing with. Those events are no longer subscribed.
41. `autorun --no-bootstrap` wrote its flag inside the quoted script path in
    Claude Code's `hooks.json`, so every hook failed to start and every tool
    call was blocked. The flag now goes after the path, and
    `autorun --enable-bootstrap` restores the shipped command.
42. `autorun --update` compared your version with the newest release, then
    installed whatever was on the default branch, moving a PyPI install onto
    unreleased code. It now installs the release it reported: the PyPI version
    for a PyPI install, the release tag for a git install.
43. With a wheel install (`uv tool install autorun-ai`), Antigravity hooks ran
    `autorun --cli ... --event <name>`, which `autorun` rejected with "invalid
    choice", so they failed. `--event` is now accepted, and a misspelled flag
    such as `--codex-hook-sorce` is now an error instead of being ignored.
    `AUTORUN_UPDATE_METHOD` now sets `--update-method`.
44. `autorun file allow`, `justify`, and `search` printed success and changed
    nothing: they wrote a policy the file gate never reads. They now write the
    session's policy (pick one with `--session`); while hooks go through the
    autorun daemon, they exit 1 and name the slash command to run in the
    session instead. `--global` now says there is no global policy.
45. `autorun --uninstall --custom-harness ...` ignored the custom harness and
    left everything the matching install put there. A custom harness named
    after a built-in one, such as `gemini`, is now refused at install; before,
    every later uninstall failed on it.
46. Uninstalling the retired `pdf-extractor` package with pip from autorun's
    own environment also deleted `extract-pdfs`, which autorun now provides. It
    is now kept and reported with the command to remove it, as the uv route
    already did.
47. `autorun --install --tool` from a wheel inside a uv tool environment failed
    before installing anything.
48. With `--codex-hook-source plugin` on a wheel install, Codex's plugin hook ran
    without autorun's dependencies.
49. Antigravity's post-install check treated "No plugins are installed." as
    proof that `ar` was registered, because "ar" is inside "are".
50. A `hook_wrapper_timeouts_seconds` value in `autorun.config.json` changed how
    long autorun planned to wait, but the hook still gave up at the built-in
    time, cutting requests short.
51. With a wheel install, Antigravity received no output from `/ar` commands
    and no other message autorun added to a prompt or model turn: the
    message was converted to Antigravity's format twice, and the second pass
    dropped it.
52. Block suggestions were built from the whole line, so
    `cd /tmp && rm -rf build` suggested `trash /tmp && rm build`. They now use
    the blocked command's own arguments.
53. With `/ar:j`, Claude Code, Codex, and the Gemini family had every new file
    refused whatever justification the agent wrote, because autorun read it only
    from the field Pi sends. On Pi, the example justification in autorun's own
    message counted as one.
54. Guards added or changed under `default_integrations` in
    `autorun.config.json` were ignored; the shipped table always applied.
55. `/ar:no regex:terraform\s+destroy` stored `terraforms+destroy`, so nothing
    was blocked, and an invalid or catastrophically slow regex was stored and then
    matched as plain text. Backslashes are now kept, and a bad regex is refused
    when you add it.
56. File guards, such as `/ar:no secrets.env` and the version-bump manifest
    guards, missed paths containing a space or Windows backslashes.
57. Project rule files (`.claude/autorun.*.local.md`) applied only when the
    daemon happened to start in that project, and then to every session. Rules
    now come from the session's project, then `~/.claude/`. README.md named
    `~/.claude/hookify.*.local.md`, which was never read.
58. A prompt that began with one of autorun's internal command names ran that
    command: "stop using sed and use the Edit tool instead" stopped autorun, and
    "activate the venv" started it.
59. Scope words such as `5m`, `3`, and `perm` were read five different ways:
    `/ar:ok rm 5min` allowed the pattern `rm 5min`, and `/ar:cache ok for 5m`
    ignored "for". Every command now uses one grammar and refuses a word it does
    not know.
60. On Codex, `ar:task resume` followed by more text in the same prompt was
    refused, and `ar:cache off` tried to read the next sentence as a duration.
    Commands now take their arguments from their own line.
61. `/ar:cache global ok` reported success while the cache gate kept blocking,
    and `/ar:cache off 1h` given twice left the gate off for good once the hour
    ended.
62. `/ar:task pause Let's discuss the release` failed with "No closing
    quotation".
63. `/ar:no format` stored the advice for `rm`, because "rm" is inside
    "format".
64. With a locale that is not UTF-8 (such as `LANG=C`), `/ar:tabs` and
    `/ar:tabw` could not see Claude Code's `❯` prompt, and window titles lost
    their non-ASCII characters: tmux printed them as `_`. autorun now asks
    tmux for UTF-8 output whatever the locale.

## For contributors

1. `installer/fs.py:decide` publishes into an existing directory that has no
   ownership marker and no entries, and reports `adopting empty directory`.
   `test_install_fs.py` covers it, including that an empty directory reached
   through a symlink stays kept and that uninstall is unchanged.
2. `installer/orchestrate.py:perform` asks `steps.switches_for` again, after
   registration in an install, for each harness that had no config directory
   before it; `qwen extensions install` is what creates `~/.qwen`. A harness
   whose directory existed still gets its switch before registration, so autorun
   stays the creator of a settings file such as `~/.codex/config.toml` and
   uninstall still removes it. `test_install_steps.py` covers both, and that no
   harness directory is created for the switch alone.
3. RELEASING.md Stage 6 derives the GitHub release's prerelease flag from the
   version with the rule `installer/entrypoint.py:_latest_version` uses. A
   stable version is published as the latest release, not as a prerelease that
   every stable install's `--self-update` would skip.
4. RELEASING.md lists the files where `1.0.0` appears only as example or test
   data. The inventory coverage test matches the version as a substring, and
   `1.0.0` is both a prefix of every earlier release candidate and a common
   example version.
5. RELEASING.md now says to bump `version` in
   `plugins/autorun/src/autorun/metadata.json`. `build_support.build_metadata`
   keeps a version already written there, so a stale one ships in the wheel.
6. RELEASING.md's live-install comment now says that `autorun --install`
   restarts the shared autorun daemon, which it already did; the comment had
   said the command restarted nothing.
7. Facts that had several hand-kept copies now have one owner each: the
   daemon's lock paths (`ipc.daemon_flock_path`,
   `ipc.daemon_restart_lock_path`), the tool-gate events and the payload
   detection table (the platform registry, with `hooks/hook_entry.py`'s stdlib
   copies pinned to it by tests), the harness no-op in `hook_entry.py`
   (`_unhandled_response`), the bug-workaround grammar
   (`config.workaround_applies`, now also used by the installer), the Codex hook
   events (`steps._CODEX_EVENTS`), link ownership (`fs._link_is_ours`),
   per-file collisions (`fs._collisions`), the default PDF backend order
   (`BACKEND_REGISTRY`), task statuses (`task_status.STATUS_POLICY`), the
   `/ar:ok` and `/ar:no` pattern grammar (`plugins._parse_pattern`), and the
   scope grammar (`scoped_allow.parse_scope_tokens`). `main.py`'s unused
   copies of the pattern parser, regex check, matcher, and justification test,
   which the tests exercised instead of the live guard, are deleted.
8. `hooks/hook_entry.py:main` now runs `try_cli`; it carried an inline copy, so
   the tests of `try_cli` tested code no hook ran. Both of its paths send the
   launching process as `_pid`, and the three detection cases
   `test_multi_platform_detection.py` pinned as strict xfails now pass.
9. `config.detect_cli_type` no longer reads the generic `session_id` key as a
   Gemini CLI payload, and `python_check.check_python_version` returns False on
   Python 3.0 to 3.9, as it already did on Python 2.
