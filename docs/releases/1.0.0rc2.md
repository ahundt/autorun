# autorun v1.0.0rc2

Date: 2026-09-01

A defect-fix candidate on 1.0.0rc1. No command was added or renamed, the task
state format is unchanged, and the install layout is the same.

`v1.0.0rc1` remains tagged and published; nothing about that tag moved. These
fixes ride this candidate instead.

## Fixed

- **A Pi or Prime agent whose tool surface has no task tools is no longer
  required to call one.** The task gates demanded a `TaskCreate` or
  `TaskUpdate` call from every session, restricted children included, so a
  child holding neither tool had no compliant action and every following tool
  call was denied. The Pi extension now reports `pi.getActiveTools()` with each
  frame, and a gate skips any session whose reported surface cannot perform the
  mutation that gate is about to require. Seven of the nine registered
  harnesses report nothing and keep the previous behavior. A reported empty set
  is an answer, not a missing one.

- **The same gate on the daemonless path.** `run_direct` serves hooks when
  `AUTORUN_USE_DAEMON=0` or the daemon is unreachable, and it built its context
  without the reported tool surface — so the fix above read "unknown" there and
  denied the restricted child anyway.

- **A finished subagent no longer receives the parent's stage instructions.**
  `SubagentStop` passed through the task lifecycle gate to the stage handler,
  which re-injected the three-stage continuation prompt into a child whose
  parent was already waiting on it.

- **Pi's `TaskCreate` requires only a subject.** `description` and `activeForm`
  were required by the tool schema, models omitted them, and the call failed
  with no task created. Both fields remain available but optional.

- **A nested `git worktree` no longer fails the release-consistency scan.** A
  worktree under `.claude/worktrees/` placed a second checkout's copy of every
  version-carrying file inside the tree. Both scans now prune any directory
  holding its own `.git`, which covers nested clones and submodules as well.

## Changed

- **Plan invocations retain their arguments.** Plan commands previously
  returned the skill body without the invocation arguments. Plan execution,
  help and activation parsed their own tails. They now read
  `ctx.command_arguments`, filled once by the matcher. Plan responses include
  the argument string once; the short command documents carry `$ARGUMENTS`.

## Upgrade notes

Nothing to migrate. Task state, config files, and `/ar` command spellings carry
over from 1.0.0rc1 unchanged.

Pi and Prime Agent users have one action. The tool-surface fix spans the
installed TypeScript extension and the Python daemon, so it takes effect only
after the extension is republished:

```bash
autorun --install
```

Hook and extension configuration is read once at session start, so restart any
running session afterwards.

## Installing

Pin the version. `uv tool install autorun-ai` does not select a prerelease:
without the pin it installs nothing while the project is RC-only, and once a
stable release exists it installs that one while looking like it installed this
candidate.

```bash
uv tool install 'autorun-ai==1.0.0rc2'

# With the PDF extraction backends:
uv tool install --force 'autorun-ai[pdf]==1.0.0rc2'

# Confirm which version answered:
autorun --version    # expect 1.0.0rc2
```

Claude Code can install from the marketplace instead:

```bash
claude plugin marketplace add https://github.com/ahundt/autorun.git
claude plugin install ar@autorun
```

For source installations, see the repository README.

## Verification

The release gate covers Python 3.10 through 3.14 on Ubuntu, Python 3.13 on
macOS and Windows, coverage, release artifacts, tmux integration, state
benchmarks, TestPyPI installation, and scratch-home marketplace installation.
Paid model calls and retired Gemini model calls remain opt-in.
